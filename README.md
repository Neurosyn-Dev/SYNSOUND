## What Is SynSound?

**SynSound** is an acoustic intelligence platform built to turn raw environmental audio into useful, structured information.

The platform is designed for applications where continuous listening, signal analysis, audio enhancement, and identification of meaningful acoustic events are important. Rather than simply recording sound, SynSound provides a unified environment for interacting with audio intelligence tools through a modern web-based interface.

The Android application brings that experience to mobile devices by providing a dedicated native Android environment around the existing SynSound web platform.

SynSound can be used as a foundation for applications involving:

* Real-time acoustic and environmental monitoring
* Continuous audio signal analysis
* Audio enhancement and inspection
* Detection of significant environmental sound events
* Acoustic intelligence workflows
* Mobile field monitoring
* Audio-focused research and experimentation
* Portable monitoring and analysis

The exact capabilities available to a user depend on the current SynSound web application and its enabled features.

---

## What Is SynSound for Android?

**SynSound for Android is an Android application wrapper for the SynSound web platform.**

It does not attempt to recreate the web application as a separate native Android product. Instead, it provides a lightweight native Android environment that allows the existing SynSound experience to operate as a dedicated Android application.

The Android wrapper provides the platform integration required for mobile use while keeping the SynSound web application itself as the primary user interface and source of functionality.

This approach allows SynSound to retain a consistent experience across platforms while taking advantage of Android capabilities such as microphone access, fullscreen presentation, lifecycle management, native file handling, and Android navigation.

## Key Features

* **High-Performance WebView Engine**
  Configured for modern JavaScript applications with DOM storage, local/session storage, cookie persistence, hardware acceleration, Web Audio support, and modern web APIs.

* **Edge-to-Edge Fullscreen Layout**
  Provides an immersive application experience with appropriate Android window-inset handling for status bars, navigation bars, gesture navigation, display cutouts, and notches.

* **Web Audio & Microphone Integration**
  Supports Android's runtime `RECORD_AUDIO` permission and WebView media permission handling so SynSound can access microphone functionality when required.

* **Real-Time Acoustic Workflows**
  Provides the Android environment required for SynSound's existing audio analysis, monitoring, enhancement, and environmental event-detection functionality.

* **Minimal Native Navigation**
  Includes a simple native bottom Back button while also integrating Android's system Back behavior with WebView navigation history.

* **File Upload Support**
  Provides Android-native file selection for audio, images, and other supported files used by the SynSound web application.

* **File Download Support**
  Supports downloads generated by the web application through Android's native download mechanisms.

* **Authentication & Session Persistence**
  Preserves appropriate cookies and WebView storage so existing SynSound authentication and sessions can function normally.

* **Network Resilience**
  Provides a clean connection-error state with retry functionality when the SynSound platform cannot be reached.

* **WebView Crash Recovery**
  Handles WebView renderer failures and provides a recovery path instead of leaving the user with an unusable blank screen.

* **Secure Web Environment**
  Uses HTTPS, normal Android/WebView certificate validation, disabled cleartext traffic, minimal permissions, and disabled WebView debugging in release builds.

* **Modern Android Lifecycle Handling**
  Designed to survive normal background/foreground transitions, screen locking, application recreation, and other standard Android lifecycle events without unnecessary page reloads.

* **Modern Brand Identity**
  Uses Android's modern splash-screen system and adaptive launcher icon resources.

## How It Works

The architecture is intentionally simple:

```text
┌─────────────────────────────────────────┐
│              SynSound App               │
│                                         │
│   ┌─────────────────────────────────┐   │
│   │        Native Android           │   │
│   │           Activity              │   │
│   │                                 │   │
│   │  ┌───────────────────────────┐  │   │
│   │  │                           │  │   │
│   │  │       Android WebView     │  │   │
│   │  │                           │  │   │
│   │  │ https://synsound-beta...  │  │   │
│   │  │                           │  │   │
│   │  └───────────────────────────┘  │   │
│   │                                 │   │
│   │       Native Bottom Back        │   │
│   └─────────────────────────────────┘   │
│                                         │
└─────────────────────────────────────────┘
```

The Android application provides the native environment.

The **SynSound web application provides the core functionality and interface**.

This keeps the Android client lightweight and avoids maintaining two separate implementations of the SynSound platform.

## Why an Android Wrapper?

The Android wrapper exists to make SynSound easier to use on mobile devices while maintaining the same core web experience.

It provides:

* A dedicated SynSound application icon
* A browser-free fullscreen experience
* Android microphone integration
* Native Android permissions
* Native file selection
* Android download support
* Android lifecycle integration
* Native Back navigation
* Better mobile presentation
* A foundation for future Android-specific capabilities

Users can launch SynSound directly from Android like a normal application without manually opening a browser and navigating to the web platform.

## Security

SynSound for Android is designed to keep the native wrapper as small and controlled as possible.

Security-related design principles include:

* HTTPS-only primary application communication
* Android/WebView SSL certificate validation
* Cleartext traffic disabled
* Minimal Android permissions
* Runtime microphone permission handling
* No unnecessary JavaScript bridges
* No unnecessary native APIs exposed to web content
* No hardcoded credentials or API keys
* No password storage by the wrapper
* No authentication-token logging
* WebView debugging disabled in release builds
* Android application sandboxing

The wrapper does not attempt to bypass or weaken Android or WebView security controls simply to make the application function.

---

## Privacy & Microphone Access

SynSound may use the device microphone for features that require live audio input.

Android microphone access is controlled through the standard Android permission system.

The application should request microphone permission when it is actually needed rather than unnecessarily requesting it immediately at startup.

Microphone access is intended to support the SynSound application's acoustic monitoring and analysis functionality.

Users can manage microphone permission through standard Android system settings.

## Getting Started

### Requirements

To build SynSound for Android, you will need:

* Android Studio
* Android SDK 35
* JDK compatible with the project's Gradle/Android toolchain
* Android SDK Build Tools
* A connected Android device or emulator

### Build

Clone the repository and open the project in Android Studio.

Then allow Gradle to synchronize the project and build the application using the standard Android build tools.

For a debug APK, the typical Gradle command is:

```bash
./gradlew assembleDebug
```

On Windows:

```powershell
.\gradlew.bat assembleDebug
```

The resulting APK will be generated under the project's:

```text
app/build/outputs/apk/
```

---

## Production Builds

For production distribution, create a properly signed release build.

Example:

```bash
./gradlew assembleRelease
```

On Windows:

```powershell
.\gradlew.bat assembleRelease
```

Release signing credentials should be managed securely and **must not be committed to the repository**.

## Development Philosophy

SynSound for Android intentionally follows a **lightweight wrapper architecture**.

The Android project is not intended to become a second, independent implementation of SynSound.

Instead:

> **SynSound Web = Core application**
> **SynSound Android = Native Android environment**

This keeps the mobile client easier to maintain and allows improvements made to the web application to become available to Android users without requiring the entire application to be rebuilt as native Android software.
